作业2  第3小题：用 C 语言实现后察看反汇编代码并加注释
================================================================

环境：DOSBox 0.74 + Turbo C++ 3.00（16 位 DOS 编译器）
源文件：ascii3.c        可执行文件：ascii3.exe


一、C 源程序（ascii3.c）
----------------------------------------------------------------

    #include <stdio.h>

    int main(void)
    {
        int i;

        for (i = 0; i < 26; i++) {
            putchar('a' + i);          /* 输出当前字母 */
            if ((i + 1) % 13 == 0)     /* 每输出 13 个换一行 */
                putchar('\n');
        }

        return 0;
    }


二、编译和察看反汇编所用的命令
----------------------------------------------------------------

1) 编译链接，生成 16 位 DOS 可执行文件：

    D:\> path d:\tc\bin
    D:\> tcc -Id:\tc\include -Ld:\tc\lib ascii3.c

2) 运行，验证输出和两个汇编版本完全一致：

    D:\> ascii3
    abcdefghijklm
    nopqrstuvwxyz

3) 用 DEBUG 反汇编：

    D:\> debug ascii3.exe
    -u 0 400                 （从代码段偏移 0 反汇编到 400H）
    -q

   程序装入内存后代码段定位在 076A，所以下面的地址都写成 076A:xxxx
   的形式（这个段号每次运行都不同，不影响阅读）。

四、C 语句和汇编指令的对应关系（小结）
----------------------------------------------------------------

1) 局部变量 int i
     挂在栈上，用 [BP-02] 访问。"为局部变量分配空间"就是 SUB SP,2 这一句。

2) 函数序言 / 尾声
     序言：PUSH BP → MOV BP,SP → SUB SP,2
     尾声：MOV SP,BP → POP BP → RET
     和你手写的汇编里用栈保存数据是同一个道理，只是编译器用 BP 做基准。

3) for (i = 0; i < 26; i++)
     初始化  MOV WORD PTR [BP-02],0
     条件    CMP WORD PTR [BP-02],1A  +  JL（有符号"小于"用 JL）
     自增    INC WORD PTR [BP-02]

4) 'a' + i
     就是 MOV AL,[BP-02] + ADD AL,61。编译器发现 i 一定小于 26，
     所以只取低字节参与运算，这样指令更短、更快。

5) putchar(c)
     Turbo C 里 putchar 是个"宏"，展开后是两条路：
       · 快路径：直接塞进 stdout 缓冲区  —— MOV BX,[00CC] / INC [00CC] / MOV [BX],AL
       · 慢路径：缓冲区满了才 CALL __fputc
     这正好说明"C 里一句 putchar，编译出来可能是一大段代码"。

6) (i + 1) % 13 == 0
     求余用除法实现：CWD（符号扩展）→ IDIV BX（BX=13）→ 余数在 DX 里，
     再用 OR DX,DX 判断余数是否为 0，然后 JNZ 跳过换行。
     这也是为什么"取模运算比较慢"——它背后是一条除法指令。

7) return 0
     XOR AX,AX，即把返回值 AX 清 0。


五、和手写汇编版（第 1、2 小题）的对比
----------------------------------------------------------------

· 手写版：自己安排寄存器（把字符放在 BL），用 int 21H 的 02H 功能逐个字符输出，
  一切都在自己掌控之中，代码短、直接。
· C 版：编译器统一用"栈帧 + 局部变量"的套路，输出走标准库的缓冲机制，
  同样一件事要经过缓冲判断、必要时还要调用 __fputc。
  好处是不用管细节、可移植；代价是代码更长、执行路径更多。
